# F-01 – Unhandled Application Exceptions on Salary and Report Export Endpoints Resulting in Information Disclosure Risk

**Series:** F  
**Likelihood × Impact:** L 3 × I 4 = R 12 🟠 High  
**Evidence Confidence:** High  
**Affected Asset / System:** Payroll Slip Module (`RepSlip.aspx`), DevExpress Report Viewer (`DXXRDV.axd`), Login Module (`login.aspx`) บน IIS (`ORG1-APP1`)  
**Target / Environment:** Production  
**Analysis Date:** 2026-11-26  
**Log Range:** 2025-11-19 00:00:00 – 2025-11-28 23:59:59 (`u_ex251119.log` – `u_ex251128.log`)  
**Evidence Sources:** `result_overview.txt`, `result_deep.txt`, `u_ex251120.log`, `u_ex251121.log`, `u_ex251125.log`, `u_ex251127.log`

---

## Risk Statement

เนื่องจากเว็บแอปพลิเคชันบน IIS เกิดข้อผิดพลาดภายในเซิร์ฟเวอร์โดยไม่ได้รับการจัดการ (Unhandled Exception — HTTP `500.0`) บนหน้าสำคัญได้แก่ หน้าเข้าสู่ระบบ (`login.aspx`), หน้ารายงานสลิปเงินเดือน (`RepSlip.aspx`) และตัวส่งออกรายงาน (`DXXRDV.axd`) รวมถึงเกิดข้อผิดพลาดดังกล่าวเมื่อมีคำขอที่ไม่ได้ยืนยันตัวตน (`User:-`) ส่งเข้ามา อาจทำให้เซิร์ฟเวอร์ส่งคืนข้อความแจ้งข้อผิดพลาดทางเทคนิค (Stack Trace, โครงสร้างฐานข้อมูล หรือพาธไฟล์ระบบ) กลับไปยังผู้เรียกใช้งาน ส่งผลให้เกิดความเสี่ยงต่อการเปิดเผยข้อมูลโครงสร้างระบบภายในและกระทบต่อความพร้อมใช้งานของบริการ

---

## เหตุผลการให้คะแนน

- **Likelihood 3:** พบเหตุการณ์ HTTP `500.0` จำนวน 7 ครั้ง กระจายตัวใน 4 วัน (`2025-11-20`, `2025-11-21`, `2025-11-25`, `2025-11-27`) และเกิดขึ้นซ้ำในหลายโมดูลของแอปพลิเคชันทั้งจากผู้ใช้งานภายในและ IP ภายนอก
- **Impact 4:** ข้อผิดพลาดเกิดขึ้นบนโมดูลสลิปเงินเดือน (`RepSlip.aspx`) และระบบส่งออกรายงาน PDF (`DXXRDV.axd`) ซึ่งจัดการข้อมูลส่วนบุคคลที่มีความอ่อนไหวสูง (ข้อมูลค่าตอบแทน) หากการเกิด Error เปิดเผยรายละเอียดทางเทคนิคหรือทำให้ระบบรายงานหยุดชะงักจะกระทบต่อความลับและความเชื่อมั่นในระบบหลัก
- **Risk Level:** High (12) — เกิดข้อผิดพลาดซ้ำในโมดูลที่มีความสำคัญสูงและเกี่ยวข้องกับคำขอที่ไม่ได้ยืนยันตัวตน

---

## หมวดหมู่ความเสี่ยง

- **Primary Category:** Information Disclosure & Technical Exposure Risk
  - การเกิด Unhandled Exception (`500.0`) บนหน้าประมวลผลข้อมูลสำคัญซึ่งเสี่ยงต่อการเปิดเผยรายละเอียดทางเทคนิคของระบบ
- **Secondary Categories:**
  - **Error-Based Exploitation:** พบรูปแบบการเกิด Error ซ้ำเมื่อส่งพารามิเตอร์เฉพาะหรือคำขอที่ไร้ Session
  - **Insecure Application Configuration:** ขาดการจัดการ Exception แบบรวมศูนย์และการตั้งค่า Custom Error Pages
  - **Service Disruption & Availability Loss:** ผู้ใช้งานและระบบรายงานไม่สามารถสร้างสลิปเงินเดือนหรือส่งออก PDF ได้เมื่อเกิด `500.0`

## หลักฐาน

### E-01 – การเกิด HTTP 500.0 บนโมดูลสลิปเงินเดือน (`RepSlip.aspx`) ทั้งแบบมีและไม่มีชื่อผู้ใช้งาน

**Source:** `result_deep.txt` (หมวด 4), `u_ex251127.log:471`, `u_ex251127.log:481`, `u_ex251127.log:601`  
**Timestamp:** 2025-11-27 03:03:30, 03:03:33 และ 05:40:24

**Observed Facts:**
- รายการ `u_ex251127.log:471` (`2025-11-27 03:03:30`): IP `10.124.1.29` (`User:user100`) เรียก `GET /webname/Main/MIS/Staff/Applications/RepSlip.aspx?id=10104&periodid=256803&salarytype=9` ได้รับสถานะ `500.0`
- รายการ `u_ex251127.log:481` (`2025-11-27 03:03:33` — ห่างกัน 3 วินาที): IP `10.124.1.29` เดิม เรียก URL เดิมซ้ำอีกครั้ง แต่ฟิลด์ `cs-username` เปลี่ยนเป็น `-` และได้รับสถานะ `500.0`
- รายการ `u_ex251127.log:601` (`2025-11-27 05:40:24`): Public IP `223.24.186.106` (`User:-`) เรียก `GET /webname/Main/MIS/Staff/Applications/RepSlip.aspx?id=10104&periodid=256811&salarytype=9` และได้รับสถานะ `500.0`

**Security Interpretations:**
- แสดงว่าโค้ดฝั่งเซิร์ฟเวอร์ของ `RepSlip.aspx` ไม่ได้ดักจับข้อผิดพลาด (Exception Handling) เมื่อตัวแปร Session ว่างเปล่า (`User:-`) หรือเมื่อส่งค่า `periodid` ที่ไม่มีข้อมูลในฐานข้อมูล (เช่น งวด `256803` หรือ `256811`) ทำให้เกิด NullReferenceException หรือ Database Exception จนระบบคืนค่า `500.0`
- ยังไม่สามารถยืนยันได้ว่าหน้าเว็บแสดง ASP.NET Yellow Screen of Death (Stack Trace) หรือแสดงหน้า Custom Error เนื่องจาก IIS Log ไม่ได้บันทึกเนื้อหา Response Body

### E-02 – การเกิด HTTP 500.0 บนตัวส่งออกรายงาน (`DXXRDV.axd`) และหน้าเข้าสู่ระบบ (`login.aspx`)

**Source:** `result_deep.txt` (หมวด 4), `u_ex251120.log:388`, `u_ex251121.log:464`, `u_ex251125.log:606`, `u_ex251127.log:945`  
**Timestamp:** 2025-11-20 03:37:05 – 2025-11-27 08:28:16

**Observed Facts:**
- รายการ `u_ex251125.log:606` (`2025-11-25 01:43:03`): IP `10.104.0.63` (`User:user116`) เรียก `GET /webname/DXXRDV.axd?actionKey=exportTo&arg=%7B%22documentId%22%3A%22a197b314383249ebbc2e8e7284c7842b%22...%22format%22%3A%22pdf%22...` ได้รับสถานะ `500.0`
- รายการ `u_ex251127.log:945` (`2025-11-27 08:28:16`): Public IP `1.47.152.62` (`User:-`) เรียก `GET /webname/DXXRDV.axd?actionKey=exportTo&arg=%7B%22documentId%22%3A%22d40791a7079b4b898fb3c3e3612ef4f7%22...%22format%22%3A%22pdf%22...` ได้รับสถานะ `500.0`
- รายการ `u_ex251120.log:388` (`192.168.33.29`, `User:-`) และ `u_ex251121.log:464` (`162.120.184.62`, `User:-`) เรียก `GET /webname/Main/login.aspx?-` ได้รับสถานะ `500.0`

**Security Interpretations:**
- การเกิด `500.0` เมื่อเรียก `DXXRDV.axd` ด้วย `documentId` ที่หมดอายุหรือไม่มี Session (`User:-`) บ่งชี้ว่า DevExpress Handler พยายามประมวลผล Object ที่ไม่มีอยู่จริงโดยไม่มีการตรวจสอบสถานะ Session ก่อน
- การเกิด `500.0` บนหน้า `login.aspx` ซึ่งเป็นหน้าแรกของการยืนยันตัวตน สะท้อนถึงความไม่เสถียรของการจัดการ State หรือการเชื่อมต่อฐานข้อมูลในบางช่วงเวลา

## การวิเคราะห์ช่องโหว่และความเสี่ยง

1. **Unhandled Null/Session Exceptions in Sensitive Modules:**
   - **Evidence:** E-01, E-02
   - **Analysis:** เมื่อคำขอที่ไม่มีข้อมูลผู้ใช้งาน (`User:-`) ถูกส่งไปยัง `RepSlip.aspx` และ `DXXRDV.axd` แอปพลิเคชันเกิดข้อผิดพลาด `500.0` แทนที่จะปฏิเสธคำขออย่างปลอดภัย (`302` หรือ `401/403`) แสดงถึงการเขียนโค้ดที่สมมติว่าตัวแปร Session มีค่าอยู่เสมอโดยไม่ตรวจสอบค่า Null
   - **Potential Impact:** ผู้ไม่หวังดีสามารถจงใจส่งพารามิเตอร์ผิดรูปแบบหรือส่งคำขอไร้ Session เพื่อกระตุ้นให้ระบบแสดงข้อผิดพลาด (Error-based Probing) และเก็บข้อมูลโครงสร้างระบบ
   - **Limitation:** ไม่สามารถยืนยันได้จากการดู Log เพียงอย่างเดียวว่ามีการเปิดโหมด `customErrors="Off"` ใน `web.config` หรือไม่

2. **Operational & Information Exposure Correlated Across Endpoints:**
   - **Evidence:** E-01, E-02
   - **Analysis:** เมื่อนำข้อมูลจาก 4 วันมาเชื่อมโยงกัน (Correlate) พบว่าปัญหา HTTP `500.0` ไม่ได้เกิดเฉพาะจุดเดียว แต่กระจายทั้งในหน้า Authentication (`login.aspx`), หน้าข้อมูลเงินเดือน (`RepSlip.aspx`) และคอมโพเนนต์รายงาน (`DXXRDV.axd`)
   - **Potential Impact:** ส่งผลให้พนักงานไม่สามารถดาวน์โหลดสลิปเงินเดือนหรือรายงานได้ในจังหวะที่เกิดข้อผิดพลาด และเพิ่มความเสี่ยงด้านข้อมูลรั่วไหลหากเซิร์ฟเวอร์ส่งรายละเอียด Exception ออกไป
   - **Limitation:** ไม่มีข้อมูล `sc-bytes` หรือเนื้อหาหน้า Error Page เพื่อประเมินปริมาณข้อมูลที่ส่งกลับ

## ข้อแนะนำ

### Immediate / Short-term (Quick Win)

1. **ตั้งค่า `customErrors mode="On"` ใน `web.config` และเปิดใช้งาน Custom Error Page บน IIS**
   - **Priority:** Critical
   - **Owner:** Application Development / IIS Admin
   - **Estimated Effort:** Low
   - **Verification:** จำลองการส่งพารามิเตอร์ผิดพลาดไปยัง `RepSlip.aspx` และ `DXXRDV.axd` ต้องแสดงหน้าแจ้งเตือนทั่วไปโดยไม่ปรากฏ Stack Trace หรือเวอร์ชัน .NET

2. **เพิ่มการตรวจสอบค่า Null ของ Session ก่อนประมวลผลใน `RepSlip.aspx` และ `DXXRDV.axd`**
   - **Priority:** Critical
   - **Owner:** Application Development Team
   - **Estimated Effort:** Low
   - **Verification:** เรียกหน้าดังกล่าวในสภาวะที่ Session หมดอายุ (`User:-`) ต้องได้รับ HTTP `302` ไปหน้า `login.aspx` แทนที่จะเป็น `500.0`

3. **ตรวจสอบ Application Event Log ของ Windows Server ในช่วงเวลาเกิดเหตุ (`2025-11-20`, `21`, `25`, `27`)**
   - **Priority:** High
   - **Owner:** System Admin / DevOps
   - **Estimated Effort:** Low
   - **Verification:** ระบุสาเหตุที่แท้จริงของ Exception (เช่น NullReferenceException หรือ SQL Timeout) และบันทึกแนวทางแก้ไข

### Long-term / Architectural Fix

1. **พัฒนาระบบ Centralized Exception Handling (Global.asax / Middleware) และ Input Validation**
   - **Priority:** High
   - **Owner:** Application Development Team
   - **Estimated Effort:** Medium
   - **Verification:** ทำ Code Review และทดสอบ Fuzzing พารามิเตอร์ `id`, `periodid`, `arg` ต้องไม่มีคำขอใดหลุดเป็น HTTP `500`

2. **ติดตั้งระบบแจ้งเตือนอัตโนมัติ (Real-time Alerting) เมื่อเกิด HTTP 5xx บนเซิร์ฟเวอร์**
   - **Priority:** Medium
   - **Owner:** SOC / Infrastructure Team
   - **Estimated Effort:** Medium
   - **Verification:** ทดสอบจำลอง Error บนระบบ UAT และตรวจสอบว่าแจ้งเตือนเข้าสู่ระบบเฝ้าระวังภายใน 5 นาที
