# D-01 – Unauthenticated Direct Access to Application Endpoints Resulting in Trust Boundary Exposure

**Series:** D  
**Likelihood × Impact:** L 4 × I 4 = R 16 🟠 High  
**Evidence Confidence:** High  
**Affected Asset / System:** Staff MIS Web Application (`/webname/Main/MIS/...`) & DevExpress Document Viewer (`/webname/DXXRDV.axd`) บน IIS (`ORG1-APP1`)  
**Target / Environment:** Production  
**Analysis Date:** 2026-11-26  
**Log Range:** 2025-11-19 00:00:00 – 2025-11-28 23:59:59 (`u_ex251119.log` – `u_ex251128.log`)  
**Evidence Sources:** `result_overview.txt`, `result_deep.txt`, `u_ex251119.log`, `u_ex251122.log`, `u_ex251125.log`, `u_ex251127.log`

---

## Risk Statement

เนื่องจากเว็บแอปพลิเคชันระบบบริหารจัดการบุคลากร (Staff MIS) และโมดูลรายงาน DevExpress (`DXXRDV.axd`) เปิดให้เข้าถึงได้โดยตรงจากเครือข่ายอินเทอร์เน็ตสาธารณะ (Public IPs) โดยไม่ปรากฏกลไกการจำกัดขอบเขตเครือข่าย (Network Segmentation / VPN) หรือการบังคับยืนยันตัวตนก่อนประมวลผลคำขอในบาง endpoint อาจทำให้ผู้ใช้งานภายนอกหรือผู้ไม่หวังดีสามารถเชื่อมต่อเข้าสู่แอปพลิเคชันภายในและเรียกใช้งานฟังก์ชันสำคัญได้โดยตรง ส่งผลให้เกิดความเสี่ยงต่อการละเมิดขอบเขตความเชื่อถือ (Trust Boundary) และการเข้าถึงข้อมูลส่วนบุคคลของบุคลากร

---

## เหตุผลการให้คะแนน

- **Likelihood 4:** พบการเชื่อมต่อจาก Public IP จำนวนมากอย่างต่อเนื่องตลอดช่วงเวลา 10 วันของ Log (เช่น `49.49.243.53` จำนวน 382 requests, `49.229.213.178` จำนวน 189 requests, `1.47.152.62` จำนวน 129 requests) รวมถึงพบการเรียกใช้งาน endpoint ภายในโดยที่ `cs-username` เป็น `-` (Unauthenticated)
- **Impact 4:** ระบบที่เปิดรับการเชื่อมต่อจากภายนอกโดยตรงเป็นระบบ MIS ที่จัดการข้อมูลบุคลากร ตารางเวลาการทำงาน และข้อมูลสลิปเงินเดือน (`RepSlip.aspx`) หากขอบเขตการเข้าถึงถูกเจาะจะกระทบต่อความลับของข้อมูลพนักงานจำนวนมากและกระบวนการทำงานหลักขององค์กร
- **Risk Level:** High (16) — พบความต่อเนื่องของการเข้าถึงจากภายนอกตลอด 10 วัน ประกอบกับความสำคัญของข้อมูลบุคลากรในระบบ MIS

---

## หมวดหมู่ความเสี่ยง

- **Primary Category:** Trust Boundary & Access Control Failure
  - การเปิดให้เข้าถึงแอปพลิเคชันภายในองค์กรและโมดูลจัดการเอกสารจากเครือข่ายภายนอกโดยตรงโดยไม่มีชั้นป้องกันขอบเขตเครือข่าย
- **Secondary Categories:**
  - **Authentication & Session Management Risk:** พบการเรียกใช้งาน endpoint ภายในในสภาวะที่ `cs-username` เป็น `-`
  - **Network & Traffic Behavior Risk:** มีทราฟฟิกจาก Public IP ภายนอกเข้ามาเรียกใช้งานระบบ MIS อย่างต่อเนื่อง
  - **Data Exposure/Privacy Risk:** ระบบที่เปิดสู่ภายนอกมีการประมวลผลข้อมูลบุคลากรและเงินเดือน

## หลักฐาน

### E-01 – การเข้าถึงระบบ Staff MIS จาก Public IP ภายนอกอย่างต่อเนื่อง

**Source:** `result_deep.txt` (หมวด 5), `u_ex251122.log:509`, `u_ex251125.log:1481`, `u_ex251123.log:235`  
**Timestamp:** 2025-11-19 04:19:52 – 2025-11-27 08:28:16

**Observed Facts:**
- พบคำขอจากกลุ่ม Public IP เข้ามายังเว็บแอปพลิเคชันจำนวนมาก เช่น `49.49.243.53` (382 requests), `49.229.213.178` (189 requests), `49.237.22.105` (146 requests), `202.29.227.74` (143 requests), `1.47.152.62` (129 requests)
- ตัวอย่างรายการ `u_ex251122.log:509` (`2025-11-22 09:26:26`): IP `49.49.243.53` (`User:user2`) ส่งคำขอ `POST /webname/Main/MIS/Staff/Applications/StaffAtt.aspx?id=10121` และได้รับสถานะ `200.0`
- ตัวอย่างรายการ `u_ex251123.log:235` (`2025-11-23 06:22:03`): IP `182.232.188.32` (`User:user46`) ส่งคำขอ `GET /webname/Main/MIS/Staff/Applications/RepSlip.aspx?id=10104&periodid=256810&salarytype=9` และได้รับสถานะ `200.0`

**Security Interpretations:**
- ยืนยันว่าเว็บแอปพลิเคชันระบบ MIS ภายในถูกเผยแพร่ออกสู่เครือข่ายอินเทอร์เน็ตสาธารณะโดยตรง (Public-facing) และอนุญาตให้เข้าถึงข้อมูลการทำงานและสลิปเงินเดือนจากภายนอกองค์กรได้
- ยังไม่สามารถยืนยันได้ว่าการเข้าถึงของ `user2` และ `user46` เป็นการใช้งานจากนอกสถานที่ของเจ้าของบัญชีจริงหรือเป็นการเข้าถึงโดยมิชอบ เนื่องจากไม่มีข้อมูล GeoIP ของเจ้าของบัญชีเปรียบเทียบ

### E-02 – การเรียกใช้งาน Endpoint ภายในโดยไม่ปรากฏตัวตนผู้ใช้งาน (`User:-`) จาก Public IP

**Source:** `result_deep.txt` (หมวด 4 และ 5), `u_ex251125.log:1481`, `u_ex251127.log:945`  
**Timestamp:** 2025-11-25 02:15:45 และ 2025-11-27 08:28:16

**Observed Facts:**
- รายการ `u_ex251125.log:1481` (`2025-11-25 02:15:45`): IP `49.230.45.31` ส่งคำขอ `GET /webname/Main/MIS/Staff/Applications/StaffSchedule.aspx?id=10102` โดยฟิลด์ `cs-username` เป็น `-` และได้รับสถานะ `200.0`
- รายการ `u_ex251127.log:945` (`2025-11-27 08:28:16`): IP `1.47.152.62` ส่งคำขอ `GET /webname/DXXRDV.axd?actionKey=exportTo&arg=%7B%22documentId%22%3A%22d40791a7079b4b898fb3c3e3612ef4f7%22...` โดยฟิลด์ `cs-username` เป็น `-` และระบบประมวลผลจนเกิดสถานะ `500.0`

**Security Interpretations:**
- แสดงถึงช่องโหว่ด้านการแบ่งแยกขอบเขตความเชื่อถือ (Trust Boundary) และการตรวจสอบสิทธิ์ในระดับ Session/Authentication ก่อนส่งคำขอเข้าสู่ Handler ของแอปพลิเคชัน
- สำหรับรายการ `StaffSchedule.aspx` ที่ได้ `200.0` โดย `User:-` อาจเกิดจากการที่แอปพลิเคชันใช้ Custom Form Authentication ที่ไม่ผูกกับ IIS `cs-username` ในบางหน้า หรือเปิดให้เข้าถึงหน้าดังกล่าวได้โดยไม่ต้องล็อกอิน

## การวิเคราะห์ช่องโหว่และความเสี่ยง

1. **Direct Internet Exposure of Internal MIS Modules:**
   - **Evidence:** E-01
   - **Analysis:** ระบบ MIS สำหรับบุคลากร (`StaffAtt.aspx`, `RepSlip.aspx`) เปิดให้ Public IP เชื่อมต่อตรงผ่าน HTTP/HTTPS โดยไม่ผ่าน VPN หรือ Zero Trust Network Access (ZTNA) ทำให้พื้นผิวการโจมตี (Attack Surface) เปิดกว้างสู่ภายนอก
   - **Potential Impact:** ผู้โจมตีจากภายนอกสามารถพยายามทำ Credential Stuffing, Brute-force หรือโจมตีช่องโหว่ของแอปพลิเคชันได้โดยตรง
   - **Limitation:** ใน Log ไม่พบหลักฐานการเจาะระบบสำเร็จจากกลุ่ม Public IP เหล่านี้

2. **Weak Trust Boundary Enforcement on Application Handlers:**
   - **Evidence:** E-02
   - **Analysis:** คำขอจากภายนอกที่ไม่มีค่า `cs-username` (`User:-`) สามารถส่งพารามิเตอร์เข้าถึง `StaffSchedule.aspx` (`200.0`) และกระตุ้นให้ `DXXRDV.axd` ประมวลผลคำสั่ง `exportTo` จนเกิด `500.0` ได้ แสดงว่าชั้นหน้าด่าน (Perimeter/WAF/IIS) ไม่ได้คัดกรองคำขอที่ไร้ Session ออกก่อนถึงตัวแอปพลิเคชัน
   - **Potential Impact:** เปิดโอกาสให้ผู้ไม่ได้รับอนุญาตเรียกใช้ฟังก์ชันภายในหรือสร้างภาระการประมวลผลให้เซิร์ฟเวอร์
   - **Limitation:** ไม่สามารถตรวจสอบ Response Body เพื่อยืนยันว่าหน้า `StaffSchedule.aspx` แสดงข้อมูลจริงหรือแสดงหน้าแจ้งเตือนให้ล็อกอิน

## ข้อแนะนำ

### Immediate / Short-term (Quick Win)

1. **บังคับตรวจสอบ Authentication Session ในทุกหน้าและทุก Handler (`.aspx` และ `.axd`)**
   - **Priority:** Critical
   - **Owner:** Application Development Team
   - **Estimated Effort:** Low
   - **Verification:** ทดสอบเรียก URL ภายในและ `DXXRDV.axd` โดยไม่ส่ง Session Cookie ต้องถูก Redirect (`302`) ไปหน้า `login.aspx` ทันที

2. **ตั้งค่า WAF / Reverse Proxy คัดกรองคำขอที่ไม่มี Session Cookie ออกก่อนถึง IIS**
   - **Priority:** High
   - **Owner:** WAF / Infrastructure Team
   - **Estimated Effort:** Low
   - **Verification:** ส่งคำขอ HTTP GET ไปยัง `/webname/Main/MIS/*` โดยไม่มี Cookie ต้องถูกปฏิเสธ (`403` หรือ `302`) ที่ชั้น WAF

3. **ตรวจสอบย้อนหลังกับเจ้าของบัญชีที่เข้าใช้งานจาก Public IP (`user2`, `user46`, `user28`)**
   - **Priority:** High
   - **Owner:** SOC / IT Security Team
   - **Estimated Effort:** Low
   - **Verification:** บันทึกผลการยืนยันตัวตนกับพนักงานเจ้าของบัญชีใน Incident Ticket

### Long-term / Architectural Fix

1. **จำกัดการเข้าถึงระบบ MIS ภายในให้อยู่หลัง VPN หรือ Zero Trust Network Access (ZTNA)**
   - **Priority:** Critical
   - **Owner:** Network / Security Architecture Team
   - **Estimated Effort:** High
   - **Verification:** ทดสอบสแกนและเชื่อมต่อพอร์ต HTTP/HTTPS จากอินเทอร์เน็ตสาธารณะโดยไม่ต่อ VPN ต้องไม่สามารถเข้าถึง `/webname/Main/MIS/*` ได้

2. **ปรับปรุงการบันทึก Log ให้ระบุ `cs-username` ครบทุกคำขอหลังผ่านการยืนยันตัวตน**
   - **Priority:** Medium
   - **Owner:** Application Development / IIS Admin
   - **Estimated Effort:** Medium
   - **Verification:** ตรวจสอบไฟล์ IIS Log พบค่า `cs-username` ปรากฏในทุก Request ที่เข้าถึงหน้าภายใน
