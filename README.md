**รายวิชา:** Introduction to CyberSecurity  
**ข้อมูลนำเข้า:** `onedrive/log/ORG1-APP1/`  
**เป้าหมาย:** ส่งมอบรายงานความเสี่ยงคุณภาพสูง **12 รายการ** (ขั้นต่ำกำหนด 10 รายการ) พร้อมไฟล์ประกอบครบถ้วนตามเกณฑ์ 15 คะแนนเต็ม

## 👥 1. รายละเอียดขอบเขตงานรายบุคคล (6 คน)

เพื่อให้การทำงานไม่ซ้ำซ้อนและครอบคลุมเกณฑ์การให้คะแนนทุกหมวด สมาชิกแต่ละคนมีหน้าที่รับผิดชอบโดยละเอียดดังนี้:

### 🔹 สมาชิกคนที่ 1: Team Lead & Log Data Analyst
* **บทบาทหลัก:** ผู้จัดการข้อมูล Log กลาง, ผู้วางโครงสร้างไฟล์ และผู้จัดทำตารางสรุปรวม
* **รายละเอียดงานที่ต้องทำ:**
  1. **สกัดและคัดกรองข้อมูล Log (`evidence/`):**
     * เขียน Script (Python / PowerShell / Bash) เพื่อดึงสถิติและพฤติกรรมผิดปกติจากไฟล์ Log ใน `onedrive/log/ORG1-APP1/` (เช่น Top IP, HTTP Status Codes 401/403/404/500, Suspicious User-Agents, Unusual HTTP Methods, Path Traversal, Brute Force Patterns)
     * บันทึก Script (`analyze_*.py`) และผลลัพธ์ (`result_*.txt`) ลงในโฟลเดอร์ `evidence/` เพื่อใช้เป็นหลักฐานอ้างอิงร่วมกันทั้งกลุ่ม
  2. **กระจายหัวข้อและหลักฐานให้ทีม:**
     * สรุปรายการเหตุการณ์ต้องสงสัยออกมาเป็น **12 หัวข้อ** โดยจำแนก Series (`D`, `B`, `T`, `F`, `C`) ให้มีอย่างน้อย 4 Series ที่แตกต่างกัน แล้วแจกจ่ายไฟล์ Log ตั้งต้นให้สมาชิกคนที่ 2–6 นำไปเขียนรายงาน
  3. **จัดทำไฟล์ข้อมูลกลุ่ม (`00_GROUP_INFO.md`):**
     * ระบุรหัสกลุ่ม รายชื่อ รหัสนักศึกษา บทบาท และสัดส่วนการแบ่งงานของสมาชิกทั้ง 6 คนให้ชัดเจน
  4. **จัดทำตารางสรุปความเสี่ยง (`RiskList.md`):**
     * รวบรวมข้อมูลจากรายงานทั้ง 12 ฉบับมาใส่ใน `RiskList.md` ให้ครบทุกคอลัมน์ (Code, Risk Name, Series, L, I, R, Risk Level, Primary Category, Evidence Confidence, Affected Component, Short Summary, Related ISO 27002 Control)
     * จัดเรียงลำดับรายการจากความเสี่ยงสูงสุดไปต่ำสุด (Critical → High → Medium → Low)
  5. **เขียน Risk Report:** รับผิดชอบเขียนรายงานความเสี่ยงฉบับสมบูรณ์ **จำนวน 2 รายการ** (เช่น Series `B` หรือ `D`)

### 🔹 สมาชิกคนที่ 2: Quality Assurance (QA) & AI Grader Specialist
* **บทบาทหลัก:** ผู้ตรวจสอบความถูกต้องทางเทคนิค, ผู้ตรวจจับ Overclaiming และผู้จัดทำไฟล์ประเมิน AI
* **รายละเอียดงานที่ต้องทำ:**
  1. **ตรวจสอบความถูกต้องของหลักฐาน (Technical Accuracy Check):**
     * สุ่มตรวจเทียบ Log บรรทัดจริง (`E-01`, `E-02`...) ในรายงานของเพื่อนทั้ง 12 ฉบับ ว่าตรงกับไฟล์ใน `ORG1-APP1` 100% หรือไม่ (ห้ามแต่งเลข IP, Timestamp หรือ Status Code เอง)
  2. **คัดกรองการตีความเกินหลักฐาน (Overclaiming Audit):**
     * อ่านทวนส่วน *Security Interpretations* และ *Risk Statement* ของทุกรายงาน เพื่อตัดคำพูดที่สรุปเกินจริง (เช่น ตัดคำว่า "ถูกแฮกสำเร็จ", "ข้อมูลรั่วไหลแล้ว" หาก Log แสดงแค่ `403`/`404`)
  3. **ตรวจความครบถ้วนตาม Rubric (Template & Rubric Compliance):**
     * เช็กทุกรายงานว่ามีหัวข้อครบตาม `risk_template-v2.md` ไม่มีการลบหัวข้อทิ้ง
     * นับจำนวนแถวในตาราง Control ต้องมี **≥ 7 แถว** และระบุ `Related Component` ครบทุกแถว
     * เช็กตาราง Cyber Kill Chain ต้องวิเคราะห์ **ครบทั้ง 7 ระยะ**
     * เช็กการอ้างอิงต้องมีครบทั้ง **ISO/IEC 27002:2022 + กฎหมายไทย + มาตรฐานเทคนิค (MITRE/CWE/OWASP)**
  4. **ทดสอบด้วย AI Evaluation Prompt:**
     * นำ Prompt ในข้อ 7 ของโจทย์ ไปรันทดสอบประเมินรายงานของกลุ่มทีละไฟล์ก่อนส่งจริง เพื่อแก้จุดบกพร่องและคัดเลือก **6 รายงานที่สมบูรณ์ที่สุด**
  5. **จัดทำไฟล์ JSON (`GRP1_ANSWER_TEMPLATE.json`):**
     * กรอกข้อมูลสรุปของรายงานทั้ง 12 ฉบับลงใน `GRP1_ANSWER_TEMPLATE.json` ให้ตรงกับเนื้อหาในไฟล์ `.md` ทุกตัวอักษร (จำนวนแถว Control, รหัส ISO, ชื่อไฟล์)
     * ตรวจสอบรหัสนักศึกษาของทั้ง 6 คนในช่อง `signed_by` ของ `integrity_declaration`
  6. **เขียน Risk Report:** รับผิดชอบเขียนรายงานความเสี่ยงฉบับสมบูรณ์ **จำนวน 2 รายการ**

### 🔹 สมาชิกคนที่ 3: Report Writer (ชุดที่ 1 — เน้นพฤติกรรมและการบุกรุก Series `B`)
* **บทบาทหลัก:** ผู้วิเคราะห์เจาะลึกและเขียนรายงานความเสี่ยง (2 ฉบับ) + คู่ตรวจทาน (Peer Reviewer)
* **รายละเอียดงานที่ต้องทำ:**
  1. **เขียน Risk Report จำนวน 2 รายการ** (เช่น `B1.md`, `B2.md` เกี่ยวกับ Brute Force, Automated Scanning, Enumeration หรือ Credential Stuffing):
     * ตั้งชื่อเรื่องตามรูปแบบ `[Weakness/Behavior] resulting in [Security Impact]`
     * คัดลอกหลักฐาน Log จริงมาจัดหมวดหมู่ (`E-01`, `E-02`...) พร้อมเขียนคำอธิบายแยก **Observed Facts** และ **Security Interpretations** อย่างชัดเจน
     * ประเมินคะแนน Likelihood (1–5) และ Impact (1–5) พร้อมเขียนเหตุผลอ้างอิงจากหลักฐาน
     * วิเคราะห์ตาราง Control ที่ล้มเหลว/ไม่เพียงพอ **อย่างน้อย 7–10 แถว** ครอบคลุมทั้ง Firewall, WAF, IIS และ Application
     * วิเคราะห์ Gap Analysis และ Cyber Kill Chain **ครบทั้ง 7 ระยะ**
     * เขียนข้อแนะนำ (Immediate และ Long-term) พร้อมระบุ Priority, Owner, Effort และ Verification
     * ระบุ References ครบทั้ง ISO/IEC 27002:2022, กฎหมายไทย (พ.ร.บ.คอมพิวเตอร์ / ไซเบอร์ / PDPA) และ MITRE ATT&CK / CWE / OWASP
  2. **ตรวจทานงานคู่บัดดี้ (Peer Review):** อ่านทวนและเช็กคำผิด/ความถูกต้องของรายงานของสมาชิกคนที่ 4

### 🔹 สมาชิกคนที่ 4: Report Writer (ชุดที่ 2 — เน้นช่องโหว่และการตั้งค่า Series `D`)
* **บทบาทหลัก:** ผู้วิเคราะห์เจาะลึกและเขียนรายงานความเสี่ยง (2 ฉบับ) + คู่ตรวจทาน (Peer Reviewer)
* **รายละเอียดงานที่ต้องทำ:**
  1. **เขียน Risk Report จำนวน 2 รายการ** (เช่น `D1.md`, `D2.md` เกี่ยวกับ Information Disclosure, Directory Listing, Server Error 500 Exposure หรือ Unencrypted/Weak Configuration):
     * ดำเนินการเขียนครบทุกหัวข้อตามแม่แบบ `risk_template-v2.md` เช่นเดียวกับคนที่ 3
     * เน้นการวิเคราะห์ความเสี่ยงในระดับ Web Server (IIS) และ Application Configuration
     * ตรวจสอบให้แน่ใจว่าตาราง Control มี **≥ 7 แถว** และ Cyber Kill Chain มี **ครบ 7 ระยะ**
  2. **ตรวจทานงานคู่บัดดี้ (Peer Review):** อ่านทวนและเช็กคำผิด/ความถูกต้องของรายงานของสมาชิกคนที่ 3

### 🔹 สมาชิกคนที่ 5: Report Writer (ชุดที่ 3 — เน้นการโจมตีแอปพลิเคชัน Series `T`)
* **บทบาทหลัก:** ผู้วิเคราะห์เจาะลึกและเขียนรายงานความเสี่ยง (2 ฉบับ) + คู่ตรวจทาน (Peer Reviewer)
* **รายละเอียดงานที่ต้องทำ:**
  1. **เขียน Risk Report จำนวน 2 รายการ** (เช่น `T1.md`, `T2.md` เกี่ยวกับ SQL Injection Attempts, XSS Probes, Path Traversal, Command Injection หรือ Malicious Payload):
     * ดำเนินการเขียนครบทุกหัวข้อตามแม่แบบ `risk_template-v2.md`
     * วิเคราะห์รูปแบบ Payload ใน URI Query / HTTP Request จาก Log อย่างละเอียด โดยระมัดระวังไม่สรุปว่าโจมตีสำเร็จหาก Status Code เป็นการบล็อกหรือหาไม่พบ
     * เชื่อมโยง CWE และ OWASP Top 10 / ASVS ให้ตรงกับประเภทการโจมตีทางเทคนิค
  2. **ตรวจทานงานคู่บัดดี้ (Peer Review):** อ่านทวนและเช็กคำผิด/ความถูกต้องของรายงานของสมาชิกคนที่ 6

### 🔹 สมาชิกคนที่ 6: Report Writer (ชุดที่ 4 — เน้นความผิดปกติของระบบ/ไฟล์ Series `F` หรือ `C`)
* **บทบาทหลัก:** ผู้วิเคราะห์เจาะลึกและเขียนรายงานความเสี่ยง (2 ฉบับ) + คู่ตรวจทาน (Peer Reviewer)
* **รายละเอียดงานที่ต้องทำ:**

     * ดำเนินการเขียนครบทุกหัวข้อตามแม่แบบ `risk_template-v2.md`

     * ระบุ Control และข้อแนะนำเชิงป้องกัน/ตรวจจับ (Detection & Visibility) ที่สอดคล้องกับ ISO/IEC 27002:2022
  2. **ตรวจทานงานคู่บัดดี้ (Peer Review):** อ่านทวนและเช็กคำผิด/ความถูกต้องของรายงานของสมาชิกคนที่ 5

## ✅ 4. กฎเหล็กและ Checklist ก่อนส่งงาน (15 คะแนนเต็ม)

### ⚠️ ข้อควรระวังสูงสุด (จุดที่มักโดนหักคะแนน)
1. **ห้าม Overclaim (หมวด C - 3 คะแนน):** 
   * ❌ *ผิด:* "แฮกเกอร์เจาะระบบสำเร็จและขโมยข้อมูลออกไป" (ทั้งที่ Log ขึ้น Status `404` หรือ `403`)
   * ✅ *ถูก:* "พบความพยายามเข้าถึงไฟล์ระบบจาก IP ภายนอกจำนวน 500 ครั้ง แต่เซิร์ฟเวอร์ปฏิเสธคำขอทั้งหมด (HTTP 403/404) ยังไม่พบหลักฐานการเข้าถึงข้อมูลสำเร็จ"
2. **ความหลากหลายของ Series (หมวด D - 2 คะแนน):**
   * 1 รายงาน ใช้ได้เพียง **1 Series หลัก** (`D`, `B`, `T`, `F`, หรือ `C`)
   * ในภาพรวมทั้งกลุ่ม ต้องมี **≥ 4 Series ที่แตกต่างกัน** เพื่อรับคะแนนระดับดีเยี่ยม
3. **โครงสร้างบังคับในทุกรายงาน (หมวด B - 6 คะแนน):**
   * ชื่อเรื่องต้องเป็นรูปแบบ: `[Weakness/Behavior] resulting in [Security Impact]`
   * ตาราง Control ที่ล้มเหลว/ไม่เพียงพอ ต้องมี **อย่างน้อย 7 แถว** และระบุ `Related Component` (Firewall, WAF, IIS, Application)
   * ตาราง Cyber Kill Chain ต้องวิเคราะห์ **ครบทั้ง 7 ระยะ** (แม้ระยะนั้นจะไม่เกิดใน Log ก็ต้องระบุเหตุผลและหลักฐานประกอบ)

### 📋 Pre-Submission Checklist
- [ ] มี Risk Report ในโฟลเดอร์ `risks/` จำนวน **10–12 รายการ**
- [ ] ทุกรายงานมีหัวข้อครบตาม `risk_template-v2.md` ไม่มีการลบหัวข้อใดออก
- [ ] ทุกรายงานแยก **Observed Facts** และ **Security Interpretations** ชัดเจน
- [ ] ทุกรายงานมี Control Table **≥ 7 แถว** พร้อมระบุ Related Component
- [ ] ทุกรายงานมี Cyber Kill Chain **ครบ 7 ระยะ**
- [ ] ทุกรายงานมี Gap Analysis พร้อมระบุ Category ถูกต้อง
- [ ] ทุกรายงานอ้างอิงครบทั้ง **ISO/IEC 27002:2022 + กฎหมายไทย + มาตรฐานเทคนิค (MITRE/CWE/OWASP)**
- [ ] `RiskList.md` ครบทุกคอลัมน์ และจัดเรียงจากระดับความเสี่ยงสูงไปต่ำ (Critical → Low)
- [ ] `GRP1_ANSWER_TEMPLATE.json` กรอกครบทุก field และตรงกับเนื้อหาในไฟล์ `.md`
- [ ] สมาชิกทั้ง 6 คน มีชื่อและรหัสนักศึกษาใน `integrity_declaration` ครบถ้วน
